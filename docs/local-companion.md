# Kairo Local Companion Architecture & Runtime Guide

## 1. Overview & Trust Architecture

The **Kairo Local Companion** is a secure, defense-in-depth local device runtime that empowers Kairo to interact with the user's personal workstation (Screen, Mouse, Keyboard, Audio, Camera, and restricted Filesystem) **without ever exposing unrestricted desktop control or remote shell access to the cloud**.

```
                   ☁️ KAIRO CLOUD / API BACKEND
                                │
                  Authenticated Mutual TLS / Token
                  Short-Lived Action Approvals
                                │
                                ▼
                   🖥️ KAIRO LOCAL COMPANION
                                │
         ┌──────────────────────┼──────────────────────┐
         ▼                      ▼                      ▼
  Local Policy Engine    Action Registry      Local Emergency Stop
  (Independent Bounds)   (Strict Allowlist)   (Hardware Kill Switch)
         │                      │                      │
         └──────────────────────┼──────────────────────┘
                                │
          ┌─────────────┬───────┴──────┬─────────────┐
          ▼             ▼              ▼             ▼
       Screen         Mouse        Keyboard      Filesystem
     (Explicit)     (Bounded)    (Restricted)   (Allowlisted)
          │             │              │             │
          ├── Microphone (Local Wake Word, Explicit Push)
          ├── Speaker (Interruptible TTS)
          └── Camera (Explicit Single Frame, Visible Status)
```

### Core Trust Principles
1. **Never an Unrestricted Shell**: Arbitrary shell commands (`powershell`, `bash`, `cmd`, `exec`, `subprocess`), arbitrary python interpreters, and process spawning are **strictly forbidden** and absent from the action registry.
2. **Defense in Depth**: Every action requires triple authorization:
   $$\text{Effective Permission} = \text{Cloud SecurityCenter Auth} \land \text{Local Policy Verification} \land \text{Human Approval (where required)}$$
3. **Fail-Closed by Default**: At boot, after a crash, on restart, or upon 15 minutes of user inactivity, all sensitive capabilities automatically decay to `OFF`.
4. **Dual Emergency Stop**: A hardware-level emergency stop can be triggered locally via hotkey/CLI/system tray **even if the workstation is completely offline or network connectivity is severed**.
5. **No Long-Lived Plaintext Secrets**: Device tokens and cryptographic keys are hashed and stored in secure credential storage.

## 2. Device Identity & Registration

### Unique Device Identity
Device identity is generated by `DeviceIdentityManager` (`companion/src/device/identity.py`). It computes a deterministic SHA-256 digest from stable hardware attributes (CPU architecture, machine GUID/UUID, and system profile) prefixed with `kairo_dev_`.
- **Identity Isolation**: Hostnames alone, IP addresses alone, or usernames alone are never used as identifiers.
- **Hardware Binding**: Cloned virtual machines or spoofed requests produce mismatched fingerprints.

### Pairing Flow
```
User logs into Kairo Command Center
  │
  ▼
Companion CLI initiates pairing:
  `python -m companion.src.main register --url http://api.kairo.ai --token <USER_SESSION_TOKEN>`
  │
  ▼
Companion generates registration payload:
  { device_id, device_name, os_name, os_version, companion_version, public_key }
  │
  ▼
Kairo Cloud authenticates user session & records device as ACTIVE
  │
  ▼
Cloud generates HMAC-SHA256 device secret (`kairo_dtk_...`)
  │
  ▼
Companion stores credentials encrypted in local vault (`LocalCredentialVault`)
  │
  ▼
Companion transitions to READY state
```

### Device Lifecycle States
- `PENDING`: Registration initiated, awaiting handshake completion.
- `ACTIVE`: Fully paired and permitted to establish command sessions.
- `REVOKED`: Disowned by the user in Settings or Cloud SecurityCenter. Credentials permanently invalidated; automatic reconnection strictly rejected.
- `DISABLED`: Temporarily gated from receiving actions.

## 3. Secure Transport & Session Protocol

### Transport Protocol
Communication between Kairo Cloud and Companion uses TLS 1.3 with short-lived session credentials.
- **Payload Schema**:
  ```json
  {
    "command_id": "cmd_e9a18f2d",
    "device_id": "kairo_dev_108a96fc9f",
    "sequence_number": 1042,
    "action": "screen.capture",
    "parameters": {},
    "authorization_context": "sig_hmac_sha256_scoped",
    "approval_id": "appr_77b312",
    "timestamp": 1725876400,
    "ttl_seconds": 30
  }
  ```

### Anti-Replay & Ordering Rules
- **Time-To-Live (TTL)**: Commands older than 30 seconds are rejected with `COMMAND_EXPIRED`.
- **Idempotency**: Processed `command_id` entries are tracked; retried duplicate commands are discarded without re-executing side effects.
- **Strict Monotonic Ordering**: Out-of-order sequence numbers are rejected.
- **Offline Purge**: If network connection drops, pending commands are purged to prevent unexpected execution upon reconnection.

## 4. Action Registry & Risk Classifications

Actions are strictly immutable and registered in `companion/src/permissions/registry.py`.

| Action Name | Description | Risk Level | Approval Required? | Default Timeout |
| :--- | :--- | :--- | :--- | :--- |
| `screen.capture` | Single screenshot of primary display | `READ_ONLY` | No | 5.0s |
| `screen.observe` | Bounded visual region snapshot | `READ_ONLY` | No | 5.0s |
| `mouse.move` | Move cursor to bounded (x, y) coordinates | `LOW_RISK` | No | 3.0s |
| `mouse.click` | Left/right/middle click | `LOW_RISK` | No | 3.0s |
| `mouse.double_click` | Bounded double click | `LOW_RISK` | No | 3.0s |
| `mouse.scroll` | Vertical/horizontal scroll units | `LOW_RISK` | No | 3.0s |
| `keyboard.type` | Bounded unicode typing (non-sensitive) | `HIGH_RISK` | **Yes** | 5.0s |
| `keyboard.press` | Single key or modifier shortcut | `HIGH_RISK` | **Yes** | 5.0s |
| `audio.record` | Explicit voice snippet capture | `LOW_RISK` | No | 15.0s |
| `audio.play` | Interruptible TTS voice feedback | `LOW_RISK` | No | 30.0s |
| `camera.capture` | Single webcam photo with visible alert | `HIGH_RISK` | **Yes** | 5.0s |
| `filesystem.read` | Read file within allowlisted directory | `READ_ONLY` | No | 10.0s |
| `filesystem.write_restricted` | Write/modify file inside allowlist | `HIGH_RISK` | **Yes** | 10.0s |
| `filesystem.delete_restricted` | Delete file inside allowlist | `DESTRUCTIVE` | **Yes** | 10.0s |

> [!CAUTION]
> **Forbidden Actions**: `shell.execute`, `process.spawn`, `system.reboot`, `registry.edit`, `socket.raw` are completely forbidden and hard-rejected at both cloud and local policy engines.

## 5. Local Policy & Defense-in-Depth

The `LocalPolicyEngine` (`companion/src/security/policy.py`) runs on the user's device and makes autonomous decisions independent of cloud instructions:
1. **Risk Downgrade Prevention**: Even if the cloud claims an action has `READ_ONLY` risk, the local registry's risk level is authoritative and immutable.
2. **Capability Gates**:
   - `computer_control_enabled`: Controls mouse and keyboard actions.
   - `microphone_enabled`: Controls audio recording.
   - `camera_enabled`: Controls webcam capture.
   - `filesystem_restricted`: Controls workspace file operations.
3. **Sensitive Context Detection**: Keyboard typing actions inspect target text against regex heuristics for API tokens, passwords, private keys, and credit cards. The companion refuses to type secrets.
4. **Approval Verification**: High-risk and destructive actions must carry a signed `ApprovalArtifact` verified against the user's device key, scoped to that specific action and target path, and valid for less than 5 minutes.

## 6. Subsystem Capabilities

### Screen Capture & Privacy
- **Explicit Single Frame**: Captures a single image frame on demand.
- **No Hidden Background Video**: Continuous screen recording without user visibility is completely absent.
- **Privacy Indicator**: When a capture occurs, the companion displays a visible notification/status update to the user.

### Mouse & Keyboard
- **Coordinate Boundary Checks**: Mouse movements outside screen dimensions are clamped and validated.
- **Computer Control States**:
  - `OFF` (Default): All input injection disabled.
  - `ARMED`: Ready for explicitly approved actions.
  - `STOPPED`: Emergency stop triggered; all input hard blocked.

### Voice & Audio
- **Local Wake-Word Detection**: The `LocalWakeWordEngine` listens locally for `"Hey Kairo"` using zero cloud bandwidth.
- **Explicit Session**: Audio capture opens only upon wake word detection or push-to-talk activation.
- **Interruptible TTS**: Speaker playback can be stopped or paused instantly by the user.

### Camera Access
- **Explicit Frame Capture**: Camera defaults to `OFF`. Every capture requires human approval and turns on an active capture warning.
- **No Background Streaming**: Silent background camera activation is prohibited.

### Restricted Filesystem Sandbox
- **Directory Allowlist**: Companion can only access explicit user-approved paths (e.g. `C:\Users\pc\OneDrive\Desktop\Kairo_Ai assistant`).
- **Canonical Realpath Resolution**: Resolves symlinks and normalizes paths (`os.path.realpath`) before performing checks.
- **Traversal Prevention**: Blocks `..`, directory traversal escapes, null bytes, and Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`, `LPT1`).
- **Confirmation Dialogue Metadata**: Displays exact canonical path, action, reason, and risk level before execution.

## 7. Dual-Layer Emergency Stop

### Cloud Emergency Stop
Triggered via the Command Center topbar or API (`POST /api/v1/security/emergency-stop`). Instantly revokes session tokens and stops all running cloud agents.

### Local Offline Emergency Stop
Operates directly within the companion daemon:
- **CLI Trigger**: `python -m companion.src.main stop`
- **Global Hotkey**: `Ctrl + Shift + Alt + Esc` (or OS equivalent)
- **Local Fallback**: Works **with or without active internet**. Sets an atomic flag that immediately aborts in-flight actions and drops input listeners.

## 8. Installation & Setup

### Prerequisites
- Python 3.10+
- Modern OS (Windows 10/11, macOS 12+, or Linux Ubuntu 22.04+)

### Installation
```bash
# 1. Clone repository
git clone https://github.com/mahitss/iron_assistant.git
cd "Kairo_Ai assistant"

# 2. Install dependencies
pip install -r backend/requirements.txt
```

### Registration
```bash
# 3. Register your workstation with the running Kairo backend
python -m companion.src.main register --url http://localhost:8000 --name "Workstation" --token "default_session"
```

### Arming the Companion
```bash
# 4. View status
python -m companion.src.main status

# 5. Arm for computer control (explicit opt-in)
python -m companion.src.main arm

# 6. Test emergency stop
python -m companion.src.main stop
```

## 9. Privacy & Telemetry Specification

### What NEVER Leaves Your Workstation
- ❌ Continuous screen recording or background screenshots
- ❌ Continuous microphone audio streams
- ❌ Background webcam video
- ❌ Arbitrary filesystem contents or system directory files
- ❌ Passwords, OTP codes, or keystroke logs
- ❌ Private keys or SSH credentials

### What Leaves Your Workstation
- ✅ Companion version and OS metadata
- ✅ Device connection status (`ACTIVE`, `DEGRADED`, `OFFLINE`)
- ✅ Capability state booleans (`computer_control_enabled`, `microphone_enabled`)
- ✅ Single explicitly requested screenshots (only when authorized by the user)
- ✅ Explicit voice commands (after wake-word detection or push-to-talk)
- ✅ Security audit outcomes (`ALLOWED`, `POLICY_BLOCKED`, `EMERGENCY_STOPPED`)

## 10. Troubleshooting

| Symptom | Cause | Solution |
| :--- | :--- | :--- |
| `DEVICE_REVOKED` | The device was unlinked from Settings | Re-run `python -m companion.src.main register` to generate fresh credentials. |
| `CAPABILITY_DISABLED` | Computer control or Mic is toggled OFF | Enable the capability in Command Center **Settings → Devices** or run `python -m companion.src.main arm`. |
| `COMMAND_EXPIRED` | System clock drift or network lag (>30s) | Sync workstation NTP clock (`w32tm /resync` on Windows, `timedatectl` on Linux). |
| `FILESYSTEM_OUT_OF_BOUNDS` | Requested path is not in allowed directories | Add the target folder to `allowed_paths` in `companion/config/companion.json`. |
| `EMERGENCY_STOPPED` | Emergency stop flag is currently active | Run `python -m companion.src.main reset-stop` and reset in Command Center topbar. |
